# تحليل المشروع

## المصدر الذي تم تحليله

- المستودع: `ali-alhumse/AS`
- نقطة البداية في المستودع: `a73db37`
- نسخة التطبيق الفعلية التي تم تحليلها: `AA-main.zip` المتاح ضمن ملفات المشروع المشتركة.
- التقنية الفعلية: HTML وCSS وJavaScript وCanvas، دون build step.

## الحالة قبل المرحلة الثانية

كان التطبيق يعمل من `main.js` واحد بحجم 2,699 سطرًا، ويجمع bootstrap وإدارة الترتيب والمشاهد والرسم والبيانات والـ CSS المضمّن. كانت هناك خمس مشاهد مرتبة كما يلي:

1. ألعاب نارية تكتب `HAPPY BIRTHDAY! Najme`، مع زر Skip وانتقال تلقائي بعد اكتمال الدورة.
2. قلب مكوّن من جسيمات، مع تفاعل mouse/touch وزر Continue.
3. بطاقتان رومانسيتان محمّلتان من البيانات، مع انتقال داخلي ثم انتقال للمشهد التالي.
4. كعكة Canvas بخمس شمعات، وإطفاء الشموع بالنقر أو اللمس، ثم ظهور رسالة عيد الميلاد وزر Continue.
5. معرض صور دائري محمّل من `memories.json`، مع أزرار وسحب ولوحة مفاتيح وزر إنهاء.

كما توجد شاشة بداية بعدّاد تاريخي، وشاشة نهاية تعرض الرسائل والقلوب المتحركة، وتستخدم `localStorage` لمنع إعادة العرض تلقائيًا بعد الإنهاء.

## المحتوى والأصول

تم الحفاظ على ملفات البيانات والنصوص كما هي، مع نقلها إلى `src/data/` وتحديث مسارات التحميل فقط. تم الحفاظ على الصور الأصلية الأحد عشر والملف `images/1` دون تعديل. لم تتم إضافة صور أو نصوص شخصية جديدة.

## نقاط الترابط التي عولجت

- الاعتماد على متغيرات عامة مثل `app` و`slides` و`currentSlideIndex`.
- خلط إدارة الانتقال مع منطق كل مشهد.
- وجود شيفرة شاشة النهاية داخل `main.js` مع أصنافها ورسومها وقراءة الرسائل.
- متغيرات غير معلنة في مشهد الألعاب النارية كانت تعمل في script التقليدي، لكنها تفشل في strict mode الخاص بـ ES Modules.
- inline handler قديم في مسار خطأ المعرض لم يعد يستطيع الوصول إلى دوال module.

## ملاحظة عن مستودع AS

كان `AS` عند الفحص يحتوي على تعليمات المشروع فقط ولم يحتوِ على التطبيق. لذلك أُضيفت نسخة التطبيق المحللة إلى فرع المرحلة الثانية، مع إبقاء النسخة القديمة القابلة للاسترجاع في `legacy/`.
